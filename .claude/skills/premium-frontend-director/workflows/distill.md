# Distill an interface

## Inputs

Use the user's goal to reduce complexity, the current UI, and the behaviors/content that must remain.

## Procedure

1. Inventory elements, repeated patterns, visual effects, motion, controls, and content that contribute to user tasks.
2. Mark each as essential, useful, redundant, confusing, decorative, or unknown. Do not remove an element merely because it is unusual.
3. Reduce duplication, competing hierarchy, gratuitous animation, and weak ornament. Preserve affordances, information, brand character, and functional states.
4. Check density and responsive behavior after simplification. Ensure removing visual emphasis did not make actions or warnings hard to find.
5. Verify primary journeys and compare representative views. Document what was removed and the reason.

## Deliver

Summarize the reductions, retained behavior, actual checks, and tradeoffs.

## Acceptance

- The interface is easier to scan or operate without losing necessary information or control.
- Hierarchy remains clear and the visual identity remains appropriate.
- Removed elements do not break functionality, accessibility, analytics, or content contracts.
